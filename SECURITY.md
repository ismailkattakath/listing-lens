# Security Policy

## Why this matters more than usual

listing-lens drives scrape-harness, which sends requests to real websites on
the operator's behalf. Its safety checks are the product: a defect that lets
a request through without them is not a bug, it is the tool doing what it
exists to prevent.

Treat anything in these categories as a security issue:

- A networked command that runs **without a valid, matching approval**, or an
  approval that can be reused, forged, replayed or widened beyond its plan.
- A way past the **egress preflight**, the **politeness ceiling**, robots.txt,
  or the **stop on a challenge** or a site cooldown.
- A path that writes data **inside a git repository**, or into this repository.
- A way for a hook, a plug-in or `pipeline.toml` content to run code or reach
  the network outside the declared stages.
- Anything that prints, logs or commits a **secret value**, or a gap in
  `leak-gate` / `public-gate` that lets a forbidden literal through.

## Supported versions

Only the **latest commit on `main`** is supported. A fix in the harness
itself reaches listing-lens as a `flake.lock` bump of its `scrape-harness`
input.

## Reporting a vulnerability

**Do not open a public issue.**

Use GitHub's private reporting:
**[Report a vulnerability](https://github.com/ismailkattakath/listing-lens/security/advisories/new)**

Please include:

- The commit sha you tested.
- What an attacker or a misbehaving agent gains. Be concrete about impact.
- Minimal reproduction steps, on the synthetic test site (`tests/site`) or a fixture.
  **Never include crawled data, real URLs or secrets.**
- Your system and Nix version.

### What to expect

| Stage | Target |
|---|---|
| Acknowledgement | within **72 hours** |
| Initial assessment | within **7 days** |
| Fix published, or a stated timeline | within **30 days** |

This is a small project maintained in spare time. Those are honest targets,
not a contractual SLA. If a deadline slips you will be told, not ignored.

You will be credited in the advisory and in `CHANGELOG.md` unless you ask not
to be. Please give us a chance to publish a fix before disclosing publicly.

## Out of scope

- Vulnerabilities in the **websites** a crawl reads. Report those to the site.
- Vulnerabilities in upstream tools (Chromium, Playwright, crawlee, Nix).
  Report those upstream.
- The harness itself: report those to
  [scrape-harness](https://github.com/ismailkattakath/scrape-harness/security/advisories/new).
- A site source plug-in, which lives outside this repository.
- Reports generated by a scanner with no demonstrated impact on this code.
